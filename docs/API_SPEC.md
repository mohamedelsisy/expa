# EXPA — API Specification (v1)

Base: `/api/v1`. JSON. Auth: Sanctum bearer token (mobile) / cookie SPA. Locale: `Accept-Language: ar|en|it` or `?lang=`.

## Envelope
Success: `{"data": <obj|array>, "meta": {"locale":"ar","page":1,"per_page":20,"total":120}}`
Error: `{"error":{"code":"validation_failed","message":"…","details":{"field":["…"]}}}`
Status codes: 200/201/204, 401, 403, 404, 422, 429, 500. Rate limits: auth 5/min per IP+email, API 60/min per user, AI per plan.
List endpoints: `?page`, `?per_page` (max 100), `?sort=-created_at`, `?filter[field]=`.

## Update: production-audit remediation (2026-10-05)
Corrections to stale rows above and new endpoints.
- **AI answer shape**: `message` also carries `disclaimer` (localized safety note, shown separately from `content`; present on unsourced and sensitive answers, otherwise null), `degraded` (boolean) and `created_at`. `GET /ai/usage` returns `{limit, remaining, resets_at}` where `resets_at` is the next local midnight (ISO 8601).
- **`GET /meta`** (public, `Cache-Control: public, max-age=300`): `locales[{code,name,dir}]`, `default_locale`, `password{min_length,requires_letters,requires_numbers}`, `uploads{max_file_mb,max_files_per_document,max_total_mb_per_user,allowed_mimes}`, `ai{max_message_chars,daily_limits}`, `patente{exam_questions,exam_max_errors,exam_minutes,daily_exam_limit,daily_practice_limit}`, `reminders{default_offsets_days}`, `verification_required_for[ai_ask,patente_exams,admin]`. Clients must read limits from here instead of hard-coding them.
- **Error envelope**: every HTTP error uses `{error:{code,message,details?}}`. New codes: `method_not_allowed` (405), `bad_request`, `payload_too_large`, `unsupported_media_type`, `session_expired` (419), `service_unavailable`, `request_failed`, `scanner_unavailable` (503, upload could not be virus-checked, nothing stored, retry later), `limit_reached` (422, per-user maximum), `cannot_modify_self`, `last_super_admin`, `password_required`, `source_has_data` (409), `city_in_use` (409).
- **Auth**: `GET /auth/tokens` (own signed-in devices: id, name, last_used_at, created_at, expires_at, current), `DELETE /auth/tokens/{id}` (revoke one). Login responds `429` with `Retry-After` when the per-account guard refuses an unknown network. Staff tokens expire after 12 h. A suspended or erasing account gets `401 unauthenticated` on any request.
- **Privacy**: `POST /profile/export {password}` (same payload as GET); with `EXPORT_REQUIRE_PASSWORD=true` the GET form returns `403 password_required`.
- **Documents**: attachment download uses an RFC 6266 `Content-Disposition` (ASCII fallback + `filename*=UTF-8''`). Per-user maxima: 200 documents, 10 devices, 500 saved jobs.
- **Analytics**: `POST /analytics/events` whitelist unchanged (`guide_view`, `job_view`, `appointment_clicked`, `lesson_started`; consent header or stored consent, always 204). The backend now also counts `guide_view` (`GET /guides/{slug}`) and `job_view` (`GET /jobs/{id}`) itself when the request carries `X-Analytics-Consent: granted` or a signed-in user has analytics consent; clients must not also POST the same view. `appointment_clicked` is client-reported (the redirect to the official booking page happens client-side).
- **Billing**: `GET /billing/invoices` adds `net_minor` and `tax{rate,amount_minor,country}` only when a VAT rate was configured; webhook `POST /billing/webhook/{provider}` supports `fake` and `stripe` (`Stripe-Signature`). Subscription `status` values: `active`, `trialing`, `past_due` (grace period, access kept), `canceled`, `expired`. New notification types `payment_failed`, `payment_failed_reminder`, `subscription_ended`, `scanner_unavailable` (admins), `announcement`.
- **Translations (MVP-5)**: `PATCH /admin/{resource}/{id}/translations {translations}` on every content resource: translation text only, allowed with `{resource}.update` or `translations.update`; live (approved/published) content stays locked unless the caller may publish; workflow transitions are unchanged.
- **New admin endpoints (MVP-15)**: `GET/POST /admin/cities`, `PUT|PATCH/DELETE /admin/cities/{id}`, `GET /admin/regions` (`cities.*`); `DELETE /admin/users/{id}` (`users.delete`, starts GDPR erasure, 202; not self, not staff); `POST /admin/notifications/broadcast {title{ar,..},body{ar,..},role?}` (`notifications.send`, in-app only, 5/hour, Arabic required, 202); `GET /admin/settings` (`settings.view`, read-only, no secrets); `GET /admin/ai/knowledge`, `POST /admin/ai/knowledge/reindex` (`ai.manage_knowledge`); `GET /admin/ai/conversations`, `GET /admin/ai/usage` (`ai.view_conversations`, METADATA ONLY, never titles or messages). `GET /admin/stats` returns `billing: null` without `reports.finance`, and `system.scheduler_heartbeat_at`.

## Articles, city profiles, marketplace, community (T-060..T-063)
All responses use the standard envelope. Public lists accept `per_page` (max 50) and a whitelisted `sort`; unknown values return 422.

### Articles and cities (public)
- `GET /articles/categories`; `GET /articles?category&city&region&tag&guide&q&sort(-published_at|published_at|title)&per_page`; `GET /articles/{slug}` (adds `body`, `tags`, `seo{title,description,canonical_path,alternates}`, `related_guides`, `related_articles`, `disclaimer`). `content_type` is always `editorial`; `source` is null unless a complete source was given (never implies official).
- `GET /city-profiles?region`, `GET /cities/{slug}` (headline, summary, ordered `blocks[{key,label,title,body,info_type(official_info|general_guidance),info_label,source|null}]`, `guides` applicable to the city/region/national, `articles`, `offices_count`, `disclaimer`). `GET /guides/{slug}/local-info?city=slug` returns the city block that complements the guide category (`block` may be null).
- Admin (content engine, same workflow/permissions as guides): `/admin/articles` (permission prefix `articles`), `/admin/city-profiles` (prefix `cities`). City profile create takes `city_id`, `translations{headline,summary,seo_description}`, `blocks[{key,info_type,sort_order,source_*,translations{title,body}}]`. An `official_info` block cannot be published without a complete https source (official domain allow-list applies).

### Marketplace (third-party providers; no payments)
- Public: `GET /providers/meta`, `GET /providers?category&city&region&language&verified&online&q&sort(relevance|rating|-rating|name)`, `GET /providers/{slug}`, `GET /providers/{slug}/reviews`. Every provider carries `source_type:"third_party"`, `official:false`, `notice`, `verification{status(verified|unverified|pending|expired),label,verified_at,valid_until}`, `rating{average,count}` (approved reviews only). Contact fields appear only when the provider opted in (`show_email/phone/website`). Commission, verification basis and evidence are never public.
- Signed-in, verified email: `POST /providers/{slug}/reviews {rating 1-5, body?}` (always `pending`; one per user; not on own listing; account age and rate limits), `GET/DELETE /my/provider-reviews`, `POST /provider-reviews/{id}/report {reason,note?}`, `POST /providers/{slug}/leads {message, consent_share_contact:true, request_type?, contact_*?, preferred_language?}` (a REQUEST, not a booking; cooldown 24h per provider; 429 `lead_cooldown`), `GET /my/provider-leads`.
- Provider portal (role `provider` + owned listing; resolved from the account, never from the URL): `POST /provider/apply`, `GET|PUT /provider/profile` (live listings: edits wait in `pending_changes`, response `meta.pending_admin_approval=true`), `POST /provider/profile/submit`, `GET|POST|DELETE /provider/verification/documents`, `POST /provider/verification/request`, `GET /provider/leads`, `PATCH /provider/leads/{id} {status:seen|closed}`, `GET /provider/reviews`, `POST /provider/reviews/{id}/reply` (moderated).
- Admin: `/admin/marketplace/providers` (content workflow, prefix `providers`; create accepts `owner_user_id`, `commission_percent`, `commission_note`), `POST .../providers/{id}/changes {action:approve|reject}` (`providers.publish`), `GET /admin/marketplace/verification-queue`, `POST .../providers/{id}/verification {action:approve|reject,basis,expires_at?,reason?}`, `GET .../evidence`, `GET .../evidence/{docId}` (`providers.verify`, audited), `GET /admin/marketplace/reviews?status=pending|approved|rejected|reply_pending`, `POST .../reviews/{id}/moderate {decision,reason}`, `POST .../reviews/{id}/reply-moderate`, `GET /admin/marketplace/reports`, `POST .../reports/{id}/resolve` (`provider_reviews.moderate`).

### Community (feature flag `community.enabled`, default false: every route below answers 404 `not_found` while off)
- Public: `GET /community/meta`, `GET /community/questions?topic&city&tag&locale&answered&q&mine&sort(-created_at|-votes|created_at)`, `GET /community/questions/{id}` (answers: accepted first then votes; comments nested). Authors are never identified: clients only see `mine`. Every item has `source_type:"third_party"`, `verified:false`, a "community answer, not verified" `label`; sensitive topics add `notice`; `official_guide{slug,title,path}` is a moderator-pinned pointer to a published guide.
- Signed-in, verified email: `POST /community/questions`, `DELETE /community/{questions|answers|comments}/{id}` (own only), `POST /community/questions/{id}/answers|comments`, `PUT|DELETE /community/{question|answer}/{id}/vote` (one per user, none on own), `PUT|DELETE /community/questions/{id}/accepted-answer {answer_id}` (question author), `POST /community/{question|answer|comment}/{id}/report`, `GET|POST /community/blocks {type,id}`, `DELETE /community/blocks/{id}`. Statuses seen by the author: `pending|approved|hidden`.
- Moderation (`community.moderate`): `GET /admin/community/queue?type&status&flagged`, `POST /admin/community/{question|answer|comment}/{id}/moderate {action:approve|hide|remove,reason}`, `PUT /admin/community/questions/{id}/official-guide {guide_slug|null}`, `GET /admin/community/reports`, `POST .../reports/{id}/resolve`. (`community.restrict_users`): `GET|PUT|DELETE /admin/community/users/{id}/restriction {shadow_banned?,muted_until?,reason}`.
- Error codes: `link_not_allowed`, `too_many_links`, `invalid_length`, `duplicate_content`, `new_account_throttled`, `community_muted`, `vote_not_allowed`, `already_reported`, `review_exists`, `account_too_new`, `consent_required`, `lead_cooldown`, `provider_account_required`, `listing_incomplete`, `verification_evidence_required`.
